THE LESSONS (the module)
  1. Spec-first bounds a migration: the SPEC scoped the slice, named the vocab and the new rules, and
     froze what must NOT change (the threshold) — so the agent migrated exactly that and reported the rest.
  2. A vocab migration is ~60/40 mechanical-rename vs new-logic, and the rename half is COMPILER-GUIDED —
     the type system does most of the work; the one thing it can't see (string literals in test assertions)
     is exactly what the single red->green cycle caught. This is why migrations are agent-friendly.
  3. The real cost centre is rarely the code — here it's the 1081-line seed fixture (the schema under
     ddl-auto=validate) and the un-versioned API contract. "Measure the effort" means finding THAT, not
     counting the renamed lines.
  4. A faithful migration CARRIES YOUR BUGS FORWARD: spec-first doesn't fix BUG-API-01, it propagates it
     across the new domain unless you decide otherwise. Migration is not a cleanup.
  5. Honest scope: one slice migrated + measured; the full two-repo port extrapolates from this real
     number; the web side is inferred, not verified, and the module says so.
