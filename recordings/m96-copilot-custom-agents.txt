the M-3.3/M-7.5 convention — module + PROGRESS carry the correction):
  BLUEPRINT M-9.6 line says: "user-level agents in ~/.github/agents/, @agent syntax".
  VERIFIED: both are SURFACE-SPECIFIC, not universal —
   - @name mentions (e.g. @debugger) + user path %USERPROFILE%\.github\agents  → VISUAL STUDIO only.

  Teaching the accurate split avoids any needsVerification flag AND is the module's
  own lesson ("check your surface; a confident wrong path fails silently").

VERIFIED FACTS (verbatim quotes)
  DEFINITION
   - VS Code: "Custom agents consist of a set of instructions and tools that are applied
     when you switch to that agent." "Custom agents are defined in a `.agent.md` Markdown
     file, and can be stored in your workspace ... or in your user profile."
   - CLI: "Each custom agent is defined by a Markdown file with an `.agent.md` extension."
   - Body: "the guidelines in the custom agent file body are prepended to the user chat
     prompt." GitHub: prompt max 30,000 characters.
   - Frontmatter (VS Code): description ("shown as placeholder text in the chat input"),
     name ("If not specified, the file name is used"), tools ("A list of tool or tool set
     names ... If unset, defaults to all tools"), model, user-invocable (default true),
     disable-model-invocation ("prevent the agent from being invoked as a subagent by
     other agents", default false), agents (subagents available), handoffs. GitHub reference
     adds target (vscode | github-copilot), mcp-servers, metadata.
  SCOPES / LOCATIONS
   - repo: ".github/agents/<name>.md ... for project-specific agents."
   - user: "~/.copilot/agents/" (CLI + VS Code); Visual Studio: "%USERPROFILE%\.github\agents
     by default. You can change this location in Tools > Options > GitHub > Copilot."
   - org: "Create /agents/<name>.md in the organization's .github or .github-private
     repository for broader availability within the organization."
   - enterprise: "... in the .github-private repository of an organization that an
     enterprise owner has designated ... across all repositories in the enterprise."
   - PRECEDENCE (verbatim): "the lowest level configuration takes precedence" ...
     "a repository-level agent would take precedence over an organization-level agent,
     and the organization-level agent would override an enterprise-level agent."
  INVOCATION (per surface)
   - VS Code: agents dropdown/picker; "/agents" (Configure) and "/create-agent". NO
     documented @name mention in VS Code → NOT claimed for VS Code.
   - Visual Studio: agent picker (2026 Insiders) + "@ syntax: Type @ followed by the
     agent name in the chat input (for example, @debugger)." Requires VS 2026 v18.4+.
   - CLI: "/agent" slash; explicit ("Use the security-auditor agent on ..."); inference
     (description-driven); programmatic "copilot --agent security-auditor --prompt ...".
  ISOLATION (subagent)
   - CLI (clearest quote): "The subagent has its own context window, which can be populated
     by information that is not relevant to the main agent." (= M-9.4's isolation, second tool.)
   - VS Code: subagents via the `agents` field; disable-model-invocation gates it.
  ORG SHARING / AVAILABILITY
   - "Once you create custom agents, they become available to: Copilot cloud agent on
     GitHub.com, Copilot cloud agent in IDEs, and GitHub Copilot CLI."
  OLD NAMING
   - "Custom agents were previously known as custom chat modes." "If you have existing
     .chatmode.md files, rename them to .agent.md ... to continue using them." (Docs say
     "previously known as"/"rename to convert", NOT the literal word "deprecated" — so the
     module says "previously known as / rename", not "deprecated".)
  PLATFORM SUPPORT
   - Common file format across VS Code / VS 2026 / CLI. VS requires 2026 v18.4+. "Custom
     agents are in public preview for JetBrains IDEs, Eclipse, and Xcode."
