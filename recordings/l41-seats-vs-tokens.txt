*** SOURCING RULE THIS MODULE MUST TEACH AND OBEY ***
Vendor PRICES are the most volatile claim in the whole course. Every dollar figure from a
vendor is dated and carries "verify current pricing." The course's OWN measured RATIOS
(9.7x, 21.1x, 0.22%, 2.1x, 1:17,765) are durable — they are properties of how agents work,
not of a price list — and they are what the module actually teaches. State this distinction
to the learner; it is the difference between a module that ages badly and one that doesn't.

THE CONVERGENCE (the module's spine — and it is now literally the market structure)
=========================================================================
ALL THREE TOOLS ARE NOW HYBRID: A SEAT YOU BUY + USAGE YOU CONSUME.
  - Copilot: was pure per-seat; since 2026-06-01 it is seat + a monthly AI-credit allowance
    metered on tokens.
  - Cursor: seat tiers + two included usage pools + per-million-token rates beyond them.
  - Claude Code: either a per-seat allowance (Teams/Enterprise) or straight per-token
    (Console/API and cloud providers).
=> "Seats vs tokens" is not a framing device. It is the actual shape of every bill on the
   market, and a leader who budgets only the seat line is budgeting half the invoice.

ATTRIBUTION — AND A COURSE FINDING THAT HAS AGED (report it honestly)
=========================================================================
M-9.5 (2026-07-25) TESTED and reported: no per-subagent cost attribution, only total_cost_usd.
**THAT IS NOW OUT OF DATE.** Per costs.md (2026-07-29), `/usage` "attributes recent usage to
skills, subagents, plugins, and individual MCP servers, with each shown as a percentage of the
total. It also flags behaviors such as long context or cache misses when one accounts for 10%
or more of recent usage."
  BUT READ THE CAVEAT BEFORE CALLING IT CHARGEBACK, verbatim: "The figures are approximate and
  computed from local session history on this machine, so usage from other devices or
  claude.ai is not included." Also: Claude Code "computes the dollar figure locally from token
  counts priced at standard list rates, so it doesn't reflect promotional pricing or contracted
  discounts and may differ from your actual bill. For authoritative billing, see the Usage page
  in the Claude Console."
=> SO THERE ARE THREE GRAINS, and a leader must not confuse them:
   1. ORG / PER-USER  — billing-grade. Teams/Enterprise spend report CSV + org analytics;
      Enterprise Analytics API (`read:analytics` scope); Console dashboard + Claude Code
      Analytics API; and OpenTelemetry, which per the docs "is the only option that streams
      per-user token and cost metrics into your own observability stack in near real time."
      Copilot: budget controls + reporting at user/org/cost-center/enterprise.
   2. SESSION / MODEL — real and precise from the usage envelope [MEASURED: M-8.1's
      per-model split came straight from `modelUsage`].
   3. WITHIN-SESSION by skill / subagent / plugin / MCP server — NEW, but approximate,
      local-only, list-rate. Good for DIAGNOSIS ("what is eating my context"), NOT for
      chargeback or invoicing.
   Chargeback by team or repo: realistic. Chargeback per agent: still no.

MODULE FRAMING
=========================================================================
Analogy: capitation vs fee-for-service, the payer's own cost structure. A seat is capitation —
  fixed per person per month, forecastable from headcount, and you absorb the variance in how
  heavily each person uses it. Tokens are fee-for-service — you pay per unit of activity and
  UTILIZATION drives the bill. Every health-plan leader knows these carry different risk and
  that a hybrid arrangement means knowing which side you hold. Agent tooling is exactly that
  hybrid, and since 2026-06-01 all three vendors bill it that way.
Spine: you buy seats, you consume tokens, and everything that actually moves the variable half
  is a BEHAVIOR — carried context, turns, delivery method, governance settings — not headcount,
  not model choice, not prompt length.
Four moves: (1) split the bill into the step and the slope, and stop using seat count as a
  usage control; (2) rank the real slope drivers by measured impact (delivery 9.7x, turns
  21.1x, context size, scoping 19%) and note the one everyone reaches for first — the cheaper
  model — ranks last at 0.22%; (3) recognize that your L-03 governance decisions already set
  the meter (review-on-every-push, permission modes, approved connectors) and that login
  determines the billing path as well as the data policy; (4) know your attribution grain —
  per-user billing-grade yes, per-agent diagnostic-only — and set caps deliberately.
Hands to L-4.2 (the team budget lab), which can use the $13/active-day anchor, the TPM/RPM
  table, and the measured ratios as its inputs.
